# Ember UX audit (origin/main cb9b2ac) (moved into the repo 2026-11-09)

The UX audit, its owner decisions and fix log, moved here from a local working folder so the record
lives with the code. Screenshot names in the findings refer to the original audit folder, which is
not kept; key before/after shots are in `ux-audit-2026-10/` beside this file.

Read-only. Method: detached worktree of origin/main, `npm ci`, `npm run build`, local D1 migrations, `vite preview` on :4181. There is no sign-in gate: state lives on the device and sync is anonymous, so nothing needed bypassing. Screens were seeded with the Tech_Scope §4.6 "Mei" data plus two Inbox tasks. API calls were aborted during the walk, so every screenshot shows the "Offline. Your changes will sync…" line under the header. That line is a test artefact; the real app shows it only when offline.
Sizes: 390×844 (weighted highest), 320×640, 768, 1024, 1180, 1440×900. Screenshots are in `UXP/shots/ember-*.png`. `shoot.mjs` was re-run after the coordinator's fix (`ember-local-home`); my own pinned-bar check scrolls with `behavior:'instant'`, and Ember has no `scroll-behavior: smooth`, so the numbers hold.

Already covered, not re-reported: `docs/Verify_List.md` (iPhone safe-area, keyboard, date pickers, drag, 320/375/414/768 no-h-scroll item, "Loading today." up to 2 s before first-run, the Today step-row second-line question = UI walk #10), `docs/Improvement_Audit.md` (#25 scroll-padding for the bottom bars, #22 focus loss, #26 disabled state), ROADMAP phase-4 decisions D1–D4 (they concern the scheduler and AI, with no UI overlap; the audit's own decisions below are labelled D-A…D-D to avoid confusion).

## Verdict
Ember already feels calm and one-column on a phone: no horizontal scroll at 320 on Today, Task and Settings, the capture bar and Task-view Start bar are pinned, every target I measured is 44 px or more (the 22 px checkbox sits in a 44 px label), and all text/UI contrast measures at or above AA (ink-soft 5.9:1 on oat, lavender-deep 5.7:1 on white, field outline 3.7:1). What feels clunky is that the header with the only menu scrolls away, the first screen of the day spends 125 px on a confirm card whose "Let's go" starts nothing, the main button says "Do this first" under a label that also says "Do this first", and the phone has none of the touch baseline (tap highlight, press feedback, overscroll). The biggest single win is making the header sticky (60 px, 7% of 844) so Today, Inbox, Settings and "Wrap up the day" are never a scroll away; it needs your call on pattern (D-A).

## Decisions for Natalie

**D-A. Phone navigation pattern.** Protects: reaching Today/Inbox/Settings/Wrap up without scrolling; changes how the app feels (the hamburger is part of the calm look). Blocks EMB-UX-1, EMB-UX-2.
1. Sticky header, hamburger stays (60 px = 7% of height). Smallest change, keeps today's look; nav still costs two taps.
2. Bottom tab bar Today / Inbox / Settings (Wrap up moves to Today's header). One-tap switching and thumb reach, but it stacks with the capture bar for about 140 px (17%) of permanent chrome, which cuts against "quieter".
3. Leave as is and rely on the back gesture and a short page. Calmest, but Settings and a growing Inbox still need a scroll to the top.

**D-B. How quiet Today should be.** Protects: the "one next step" feel against four controls per row and a confirm card. Blocks EMB-UX-5, EMB-UX-6.
1. Rows keep checkbox + title; play and Not today move into the "…" menu; confirm card becomes a one-line strip. Quietest; starting a non-frog row takes two taps.
2. Only the confirm card changes (strip, or auto-confirm on first action); rows stay as they are. Fixes the 125 px, keeps one-tap start.
3. Keep both as designed; the one-tap play and the explicit morning confirm are the product. Nothing changes; costs the density above.

**D-C. Copy that makes the product's voice (you own these).** Blocks EMB-UX-4, EMB-UX-7 (label), EMB-UX-8, EMB-UX-12 (prompt).
1. Button "Start" (matches Task view and Onboarding), skip becomes "Skip for now", first-run "Today" step keeps only "Break this down", prompt becomes "What's the first small thing to do?".
2. Button "Start this first" (keeps the frog idea), skip becomes "Skip to Today", first-run "Start" begins a 2-minute timer on the task title like a Today row does, prompt unchanged.
3. Keep all current wording and only fix the duplicate onboarding buttons. Least change; the label/button echo stays.

**D-D. Brand presence in the app itself.** Protects: first-run recognisability and the share/install impression; nothing blocks on it except the heading half of EMB-UX-7.
1. Wordmark "Ember" plus the cat in first-run only; screens keep their page titles.
2. Small "Ember" wordmark beside the hamburger on every screen (page title moves below or stays).
3. No wordmark; the cat and the name in the drawer and page `<title>` are the identity. Calmest; a first-run screen with no name remains.

## Branding status
- Name in header: **missing** on every screen (the header shows the page title; "Ember" appears only in the drawer, `App.tsx:615`, and as an `sr-only` first-run heading).
- Logo: **partial**, the cat artwork and app icon exist (Today nook, Reward, `public/icon-*.png`); no wordmark.
- Favicon: **present** (`favicon.ico`, `icon-192.png`, `apple-touch-icon.png`, manifest icons incl. maskable).
- `<title>`: **present** ("Ember", set once and not per screen; fine for an app, but Back-history entries all read "Ember").
- OG image: **partial** (`og:image` is the 512 px square app icon at an absolute URL; no `og:url`, `twitter:card` or 1200×630 card).
- Palette and type: **present and consistent** (named tokens at `styles.css:6-21`, Nunito for display, Karla for body, one icon style, light only by decision).
